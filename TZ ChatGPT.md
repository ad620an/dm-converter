3. Вкладка «Создание DataMatrix»
3.1. Назначение
Пользователь загружает файл с символьными последовательностями, после чего приложение генерирует DataMatrix для каждой строки.

Необходимо предусмотреть понятное сообщение при превышении лимита.

4. Критически важное требование: управляющие символы
Символьная последовательность может содержать символы, которые визуально не отображаются.

В частности:

ASCII 29 / decimal 29;

HEX 1D;

GS (Group Separator).

Этот символ нельзя удалять, заменять, нормализовать или преобразовывать в обычный печатный символ.

Внутри приложения:

ASCII 29 = \x1D = 0x1D = GS

должен рассматриваться как один реальный байт/символ строки.

Например:

010460123456789021ABCDEF123456\x1D910123\x1D92SIGNATURE

и

010460123456789021ABCDEF12345691012392SIGNATURE

— это разные строки.

Первый вариант должен сохранять ASCII 29.

4.1. Запрет автоматической нормализации
Запрещено:

заменять ASCII 29 на пробел;

заменять ASCII 29 на ~;

заменять его на строку [GS];

удалять его;

автоматически trim-ить содержимое внутри строки;

менять регистр;

менять кодировку символов;

преобразовывать бинарные управляющие символы в Unicode-аналоги.

При отображении пользователю управляющие символы можно показывать в визуализированном виде, например:

010460123456789021ABCDEF123456␝910123␝92...

но внутреннее значение должно оставаться:

010460123456789021ABCDEF123456\x1D910123\x1D92...

11. Извлечение GTIN
Для стандартной структуры GS1 DataMatrix Честного знака использовать AI 01.

Стандартная структура начинается с:

01 + 14 цифр GTIN

Поэтому для стандартного кода:

0104601234567890...

GTIN:

04601234567890

Не удалять ведущий ноль.

GTIN должен храниться и отображаться как строка, а не как число.

Это критично для Excel/CSV.

При невозможности однозначно определить GTIN необходимо показать предупреждение, а не молча выводить неправильное значение.

14. Очень важное правило FNC1 / ASCII 29
Нельзя путать:

FNC1;

ASCII 29 / GS;

текстовое представление \x1D;

текстовое представление [GS].

Они не должны бездумно заменять друг друга.

В частности, если исходная строка содержит:

\x1D

это должен быть реальный ASCII 29.

Если библиотека генерации GS1 DataMatrix использует специальный API для FNC1/GS, использовать именно этот API.

Не делать простую замену:

"\x1D" -> "[GS]"

и передавать [GS] в генератор.

20. Декодирование должно быть lossless
Это одно из главных требований проекта.

Декодировщик должен возвращать не текстовое описание кода, а исходную последовательность байтов/символов.

Например, если внутри DataMatrix находится:

010460123456789021ABCDEF123456\x1D910123\x1D92ABC...

результат должен содержать именно:

010460123456789021ABCDEF123456\x1D910123\x1D92ABC...

где \x1D — реальный ASCII 29.

Нельзя возвращать:

010460123456789021ABCDEF123456[GS]910123[GS]92ABC...

или:

010460123456789021ABCDEF123456~910123~92ABC...

если исходным символом был ASCII 29.

23. Ключевое требование к декодеру ASCII 29
Основная проблема текущего эталонного сайта platan-datamatrix.ru заключается в том, что один нечитаемый символ декодируется неправильно.

Новая система должна быть специально спроектирована так, чтобы не повторять эту ошибку.

Необходимо выяснить на уровне используемой библиотеки декодирования:

возвращает ли библиотека ASCII 29;

возвращает ли она FNC1;

преобразует ли FNC1 в GS;

преобразует ли GS в ~;

удаляет ли GS;

преобразует ли управляющий символ в Unicode;

изменяет ли последовательность при преобразовании bytes -> string.

Особое внимание уделить участку:

DataMatrix image
      ↓
decoder
      ↓
raw bytes / codewords
      ↓
GS1 parser
      ↓
original byte sequence
      ↓
UI / TXT / CSV

Нельзя делать:

decoder → обычная строка Unicode → дальнейшая обработка

если на этом этапе теряется ASCII 29.

24. Тест на ASCII 29
Обязательно написать автоматические тесты.

Тест 1
Исходная строка:

ABC\x1DDEF

После кодирования и декодирования:

ABC\x1DDEF

должна получиться побайтно идентичная строка.

Тест 2
Исходная строка:

010460123456789021ABCDEF123456\x1D910123\x1D92ABCDEFG

После:

encode → DataMatrix → decode

результат должен быть идентичен исходной строке.

Тест 3
Проверять:

length(original) === length(decoded)

и:

byteArray(original) === byteArray(decoded)

Тест 4
Отдельно проверить позицию ASCII 29.

Например:

original.indexOf("\x1D")
===
decoded.indexOf("\x1D")

Тест 5
Проверить несколько ASCII 29 в одной строке.

невозможность разобрать GS1-структуру.

В таком случае попробовать альтернативный режим декодирования.

29. Нельзя «угадывать» потерянный символ
Критически важно:

Если декодер физически не смог получить символ, приложение не должно молча придумывать его.

Например, нельзя автоматически делать:

ABCDEF?910123

→

ABCDEF\x1D910123

только потому, что это выглядит как ожидаемая структура.

Можно определить вероятную GS1-структуру и показать:

⚠ Возможно потерян разделитель GS (ASCII 29)

но восстановление должно быть явно обозначено как предположение и не попадать в основной lossless-результат без подтверждения пользователя.

30. Проверка GS1-структуры
После декодирования желательно выполнять структурный анализ.

Например:

01 + GTIN
21 + serial
91 + key
92 + crypto

Разделители:

ASCII 29

должны учитываться при разборе.

В интерфейсе можно показывать:

Но структурированный результат не должен заменять оригинальную последовательность.

Оригинал всегда сохраняется отдельно.

42. Главный интеграционный тест
Создать DataMatrix из:

010460123456789021ABCDEF123456\x1D910123\x1D92ABCDEFGHIJKLMNOPQRSTUVWXYZ1234567890

Затем:

DataMatrix
    ↓
сгенерированный PDF/PNG
    ↓
декодировщик
    ↓
полученная строка

Полученная строка должна быть побайтно идентична исходной.

Проверка:

encode(input)
decode(encoded)

должно удовлетворять:

decode(encode(input)) === input

для всех тестовых строк, содержащих ASCII 29.

Это является главным критерием корректности приложения.
