# Техническое задание

## Веб-сервис генерации и декодирования DataMatrix кодов «Честного знака»

Необходимо разработать готовое веб-приложение для работы с DataMatrix-кодами системы маркировки «Честный знак».

В качестве функционального и визуального ориентира можно использовать сервис:

**[www.platan-datamatrix.ru](http://www.platan-datamatrix.ru)**

При этом нельзя слепо копировать его реализацию. Особое внимание необходимо уделить корректной обработке управляющих и непечатаемых символов. В референсном сервисе один из таких символов декодируется неверно.

Для выполнения задачи можно использовать имеющихся агентов:

* `datamatrix-creator.md`
* `datamatrix-decoder.md`

Если архитектура проекта предполагает разделение задач между агентами, использовать `datamatrix-creator.md` для логики генерации DataMatrix и `datamatrix-decoder.md` для распознавания и декодирования.

# 1. Общая задача

Создать веб-приложение с двумя основными вкладками:

1. **Создание DataMatrix**
2. **Декодирование DataMatrix**

Интерфейс должен быть строгим, минималистичным и профессиональным.

Тема интерфейса:

* только светлая;
* белый или почти белый основной фон;
* серые границы;
* темный текст;
* один спокойный акцентный цвет;
* без градиентов;
* без декоративных анимаций;
* без лишних иллюстраций;
* адаптивная верстка для desktop и планшетов.

Основная аудитория — пользователи, работающие с маркировкой товаров и печатью кодов «Честного знака».

Интерфейс должен быть понятным без отдельной инструкции.

# 2. Критически важное требование: сохранение исходной последовательности байтов

DataMatrix должен создаваться не просто из отображаемого текста, а из **точной исходной последовательности символов/байтов**.

В строках могут присутствовать непечатаемые управляющие символы.

В частности:

**ASCII 29 — Group Separator / GS / `0x1D`**

должен:

* корректно считываться из загружаемого файла;
* сохраняться внутри приложения;
* передаваться в DataMatrix-код;
* корректно восстанавливаться при декодировании;
* не заменяться пробелом;
* не заменяться символом вопроса;
* не удаляться;
* не превращаться в текст `"GS"`;
* не превращаться в строку `"<GS>"`;
* не заменяться переносом строки.

В UI допустимо отображать непечатаемый символ человеку в визуализированном виде, например:

`<GS>`

но это должно быть **только представление в интерфейсе**.

В фактических данных должен оставаться байт:

`0x1D`

То есть необходимо разделять:

1. исходное значение;
2. значение для отображения пользователю.

Это относится и к другим управляющим символам ASCII, если они встречаются во входной последовательности.

TXT-файл может содержать:

один код на каждой строке.

**Вариант Б:**

# 10. Генерация DataMatrix

Использовать стандарт:

**DataMatrix ECC 200.**

Необходимо убедиться, что используемая библиотека умеет работать с бинарными/управляющими символами.

При генерации нельзя преобразовывать строку в форму, которая удаляет ASCII 29.

Особое внимание уделить режимам кодирования GS1.

Для кодов «Честного знака» необходимо корректно поддерживать содержимое, включающее GS-разделители.

Если для корректного DataMatrix требуется GS1/FNC1-режим, использовать его согласно структуре исходного кода.

Не следует автоматически добавлять или удалять GS/FNC1 без понимания входных данных.

# 11. Настройка размера DataMatrix

На вкладке должен быть отдельный блок:

## Размер DataMatrix

Предусмотреть:

* автоматический;
* несколько фиксированных размеров.

Например:

* 12 × 12 мм
* 15 × 15 мм
* 18 × 18 мм
* 20 × 20 мм
* 22 × 22 мм
* 25 × 25 мм
* пользовательский

Для пользовательского размера:

`Ширина DataMatrix, мм`

`Высота DataMatrix, мм`

Для DataMatrix по умолчанию использовать квадрат с одинаковыми шириной и высотой.

Необходимо сохранять четкие границы модулей и не применять сглаживание.

Важно: запрошенный размер DataMatrix включает поле отступа (quiet zone) —
минимум один модуль (1X) с каждой стороны символа по ISO/IEC 16022.
Сам символ печатается полностью в оставшейся области, без масштабирования
и обрезки; границы модулей остаются целыми. Растр библиотеки (символ плюс
его собственная тихая зона в пикселях) не является матрицей модулей —
перед отрисовкой модули извлекаются из него явно.

# 14. Определение GTIN

GTIN необходимо извлекать из кода маркировки.

Не следует просто считать первыми 14 символами строки любой код.

Нужно учитывать структуру GS1.

Обычно GTIN находится после Application Identifier:

`01`

Пример:

`01 + GTIN-14`

Из строки:

`0104601234567890...`

необходимо получить GTIN согласно GS1-разметке.

Реализацию вынести в отдельную функцию/модуль и покрыть тестами.

---

# 15. Первые 38 символов

При выводе «первых 38 знаков DataMatrix» считать символы исходной последовательности.

При этом для визуального отображения управляющих символов можно использовать `<GS>`.

Важно:

визуализированная строка может стать длиннее исходной, поэтому сначала берутся необходимые символы исходной последовательности, а только после этого управляющие символы заменяются на обозначения для UI.

# 18. PDF для печати

При создании PDF необходимо соблюдать физические размеры в миллиметрах.

Например:

наклейка 58 × 40 мм должна иметь страницу PDF именно:

**58 × 40 мм.**

DataMatrix не должен:

* масштабироваться браузером произвольно;
* становиться размытым;
* иметь anti-aliasing по границе модулей.

Учитывать quiet zone: вокруг символа оставляется поле не меньше одного
модуля (1X). Quiet zone входит в запрошенный размер DataMatrix и не
приводит к сжатию или обрезке самого символа.

Модули DataMatrix рисуются по настоящей модульной матрице символа, а не
по пикселям растра библиотеки: в PDF — целыми прямоугольниками в мм, в
PNG — целыми пикселями, без интерполяции и размытия.

# 21. Распознавание

6. исключить дубликаты только по желанию пользователя.

---

# 22. ASCII 29 при декодировании

Это один из главных критериев приемки проекта.

Если внутри DataMatrix присутствует:

**ASCII 29 / GS / hex `1D`**

после декодирования в фактическом значении должен находиться именно:

**U+001D / byte 0x1D**

в зависимости от представления используемой библиотеки.

Нельзя возвращать вместо него:

* `?`;
* пробел;
* `GS`;
* `<GS>`;
* `\u001D` как шесть текстовых символов;
* пустую строку.

В таблице интерфейса допускается показывать:

`<GS>`

но при экспорте должен использоваться исходный управляющий символ, если выбран режим «оригинальные данные».

1. полный код маркировки, включая нечитаемые символы (GS/0x1D и другие);
2. количество.

Поддерживаются кодировки UTF-8 (с BOM и без) и Windows-1251; 0x1D сохраняется
байтом. Заголовок колонок распознаётся автоматически. Лимит — 1000 строк.

## Формирование последовательности

Каждая итоговая последовательность:

`<полный код (колонка 1)> + GS (ASCII 29, байт 0x1D) + "30" + <количество (колонка 2)>`

* `"30"` — Application Identifier (30) количества по GS1;
* последовательность — без пробелов и дополнительных знаков;
* количество — целое положительное, не более 8 цифр (ограничение AI 30);
* строки с пустым кодом или некорректным количеством помечаются ошибкой
  с указанием номера строки и причины.

## Выходной файл

CSV с одной колонкой: по одной последовательности в строке, 0x1D остаётся
настоящим байтом (не `<GS>`), форматирование CSV-поля — стандартное
(кавычки при необходимости). Имя файла предсказуемое:

`apply_YYYY-MM-DD_HHMMSS.csv`

## Предпросмотр

До формирования файла на вкладке отображаются: полный код (с `<GS>`),
количество и итоговая последовательность по каждой строке, количество
корректных/ошибочных строк. Кнопка формирования файла доступна, только
когда ошибок нет.

# 34. Библиотеки

Claude должен самостоятельно выбрать библиотеки после проверки их возможностей.

Перед интеграцией библиотеки генерации выполнить тест:

Исходная последовательность должна содержать:

`ABC` + ASCII29 + `DEF`

То есть байты:

`41 42 43 1D 44 45 46`

После цикла:

`encode -> DataMatrix -> decode`

результат должен содержать те же байты:

`41 42 43 1D 44 45 46`

Если библиотека возвращает другое значение, такую реализацию нельзя использовать как основной декодер.

# 35. Обязательные автоматические тесты

Создать тесты как минимум для следующих сценариев.

### Тест 1

Обычная строка.

Вход:

`010460123456789021ABCDEF`

### Тест 2

ASCII 29.

Несколько GS.

Вход содержит несколько `0x1D`.

* позиции;

должны совпадать.

### Тест 4

1000 строк.

Генерация проходит без потери строк.

### Тест 5

GTIN с ведущим нулем.

Ведущий ноль сохраняется.

### Тест 6

TXT с ASCII 29.

После импорта значение побайтово совпадает с содержимым файла.

### Тест 7

CSV с ASCII 29.

После импорта значение сохраняется.

### Тест 8

PDF с несколькими DataMatrix.

Все коды распознаются отдельно.

### Тест 9

Несколько страниц PDF.

В результате сохраняется номер страницы каждого найденного кода.

### Тест 10

Export TXT.

После повторного чтения экспортированного TXT ASCII 29 остается на исходной позиции.

# 36. End-to-end тест

Обязательно реализовать полный round-trip тест:

1. взять тестовую последовательность «Честного знака» с ASCII 29;
2. сгенерировать DataMatrix;
3. сформировать PNG или PDF;
4. передать этот PNG/PDF в декодер приложения;
5. декодировать;

Условие:

`decodedBytes === sourceBytes`

# 40. Важное архитектурное решение

Внутри приложения желательно не использовать обычную JavaScript-строку как единственный источник истины для исходного DataMatrix.

Необходимо предусмотреть бинарно-безопасное представление.

Например:

`Uint8Array`

или аналогичную структуру.

Можно хранить одновременно:

```text
rawBytes
displayValue
```

где:

`rawBytes`

является источником данных для DataMatrix и экспорта,

а:

`displayValue`

используется только для интерфейса.

Функция отображения может выполнять:

`0x1D -> <GS>`

но обратное преобразование для исходных загруженных данных не должно зависеть от текста интерфейса.

# 45. Главное правило реализации

**Нельзя считать задачу выполненной, если интерфейс работает, но ASCII 29 теряется или преобразуется.**

Правильность исходной последовательности важнее визуального сходства с референсным сайтом.

Основной инвариант проекта:

```text
source bytes
    ↓
DataMatrix encode
    ↓
image / PDF
    ↓
DataMatrix decode
    ↓
decoded bytes

source bytes === decoded bytes
```

Особенно:

```text
0x1D === 0x1D
```

а не:

```text
0x1D -> "?"
0x1D -> " "
0x1D -> "<GS>"
0x1D -> ""
```

Сначала обеспечить этот инвариант, затем строить остальную функциональность.
